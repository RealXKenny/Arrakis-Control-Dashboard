# Contributing to Arrakis Control Dashboard

Thank you for helping improve Arrakis Control Dashboard. Contributions of code, tests, documentation, accessibility improvements, and bug reports are welcome.

## Before contributing

- Search existing issues and pull requests to avoid duplicate work.
- Open an issue to discuss major features, breaking changes, or architectural changes before investing substantial effort.
- Follow the [Code of Conduct](CODE_OF_CONDUCT.md).
- Report security vulnerabilities privately as described in [SECURITY.md](SECURITY.md), not in public issues.

## Development workflow

1. Fork the repository and create a focused branch from the project's active development branch.
2. Make small, reviewable changes with clear commit messages.
3. Add or update tests and documentation for behavior changes.
4. Run the repository's documented formatting, linting, type-checking, test, and build commands before opening a pull request.
5. Open a pull request explaining the problem, solution, testing performed, and any migration or deployment impact.

Do not commit credentials, private keys, access tokens, production data, or real environment files. Use sanitized examples and follow the repository's environment template.

## Pull request expectations

- Describe the change and link related issues.
- Document user-facing changes and configuration changes.
- Include screenshots for visible UI changes when helpful.
- Explain database migrations, security implications, or compatibility risks.
- Respond respectfully to review feedback.

Maintainers may request changes, postpone work, or decline contributions that do not align with project goals.
