# Security audit — 2026-11-16

The sanitized findings and remediation checklist are tracked in [issue #12](https://github.com/RealXKenny/Arrakis-Control-Dashboard/issues/12). This audit covers V2 and the proposed integration of [community seasons](https://github.com/RealXKenny/Arrakis-Control-Dashboard/pull/9) and [personalization/shared UI](https://github.com/RealXKenny/Arrakis-Control-Dashboard/pull/11) into [PR #8](https://github.com/RealXKenny/Arrakis-Control-Dashboard/pull/8). It does not authorize a production deployment or merge into main.

## Findings

- **Transport hardening:** ordinary Console/adapter calls accept configured remote HTTP in production. A synthetic, mocked request confirmed that the authorization header follows that policy, with zero real network requests. Exposure depends on deployment configuration. Administrator execution and season delivery already enforce HTTPS or loopback. The issue tracks applying a consistent secure transport policy.
- **Dependencies:** the combined lockfile reports zero npm audit advisories. Main retains three moderate development-dependency alerts affecting older Vitest mocker and minimatch versions; the feature branch already carries versions outside those reported ranges.
- **Static analysis:** all seven open main-branch CodeQL alerts were inventoried. Mutable release-action tags and old regex classification need main-branch remediation. Other alerts require evidence-based triage; scanner severity is not proof of exploitability. Several current V2 implementations have already replaced the reported paths.
- **Secret scanning:** GitHub reports no open secret-scanning alerts and has push protection enabled. This is not a full-history secret audit. Local secret files and production credentials were not inspected or published.

## Controls reviewed

The review included session ownership and freshness, administrator exact-ID authorization and recent-sign-in protections, same-origin mutation boundaries, request/upload bounds, redirect refusal, asset allowlists, privacy CAS/revocation and season delivery authorization/recovery. UI tests must wait for confirmed mutation completion before checking a revoked link; reading concurrently with an unfinished mutation is not evidence of a revocation failure.

Season game delivery remains disabled by default. It requires frozen claimed rewards, fresh matching character identity, offline status, independent review and explicit administrator execution. A persisted send marker precedes a grant; uncertain outcomes require reconciliation, with no automatic resend. No game delivery was enabled or executed by the audit.

## Limits and verification

This is source/dependency review and bounded local testing, not a production penetration test. No live destructive testing, production network assessment, account compromise exercise or full-history secret scan was performed. Existing administrator MFA, session-management UI, Auth.js lifecycle, release provenance and deployment TLS decisions remain separate hardening items in the [security overview](security-overview.md).

Exact integration test and CI results are recorded in PR #8 comments so this report does not imply that incomplete checks passed. Findings remain open until separately remediated and verified. Sensitive exploit details belong in the private reporting channels described by [SECURITY.md](../../SECURITY.md).
