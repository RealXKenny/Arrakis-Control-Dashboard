# Security audit — 2026-11-26 (launch review)

This review covers the `v2` branch ([PR #8](https://github.com/RealXKenny/Arrakis-Control-Dashboard/pull/8)) as of commit `050b68f`, including the features added on 2026-11-26 (N011–N070) and the poker Discord Activity. It follows the [2026-11-16 audit](audit-2026-11-16.md). It does not by itself approve a production deployment.

## Result

No launch-blocking issue was found. Two hardening changes were made on `v2` with tests. Some items need the operator's configuration or a live check, which this source review cannot do. They are listed under [Operator actions](#operator-actions).

## Scope and method

- Static review of all 88 App Router API handlers (`src/app/api/**/route.ts`), the 33 Pages Router API entry points (`src/pages/api/`), the single server-action module, `src/proxy.ts` and `next.config.ts`.
- A script followed each route to its handler and flagged any handler with no session check or, for a write, no origin check. Each flagged handler was then read by hand.
- Manual review of authentication (Auth.js with Discord and email/password), Redis session storage, rate limiting and client address handling, image uploads, share links, the casino transfer entry point, the poker Activity server, its framing exception and its `postMessage` client.
- `npm audit` against the committed lockfile: 0 advisories (production and development).

This was a source and dependency review with unit tests. No live penetration test, production network scan or Discord Activity session was run.

## Controls confirmed

- **Sessions.** The cookie holds only an opaque 256-bit session ID. In production it is `__Host-` prefixed, `HttpOnly`, `Secure` and `SameSite=Lax`. The Redis record is the authority. It is re-verified against Discord every 30 minutes, a fresh login never inherits an old session ID, and sign-out deletes the record.
- **Authorization.** Every `/api/v2` handler requires a dashboard session, except: public changelog reads, the poker routes (which use their own Activity bearer token), and the bot world read (which needs `BOT_API_TOKEN`, compared in constant time). Guild routes re-check membership or leadership against the Console on each request. Ownership always comes from the session, never from the request body.
- **Writes.** Every write handler checks `Origin` against `APP_URL` and rejects cross-site `Sec-Fetch-Site`. Server actions rely on Next.js's built-in origin check. Bodies have size limits and are parsed against strict schemas.
- **Password login.** Passwords are hashed with scrypt (N=2¹⁵). Unknown emails cost the same as wrong passwords. Attempts are limited per email, per address and email together, and per address. Every password login also refreshes Discord roles, so a member who leaves the guild loses email access. Refresh tokens are sealed with AES-256-GCM.
- **Redirects.** `safeNextPath` allows only same-site relative paths.
- **Uploads.** Screenshots and evidence images are sniffed, decoded by sharp with a 16-megapixel input limit, limited to a single frame and re-encoded to WebP. They are served `private, no-store` with `nosniff` and a sandboxing CSP.
- **Headers.** Each request gets a CSP nonce with `script-src 'self' 'nonce-…'`, and `object-src 'none'`. `frame-ancestors 'none'` and `X-Frame-Options: DENY` apply everywhere except the poker Activity page. Responses also set COOP `same-origin`, CORP `same-origin` and HSTS in production. API responses are `no-store`.
- **Poker Activity.** Only `/activity/poker`, and `/` when it carries Discord's `frame_id` and `instance_id`, may be framed, and only by `discord.com`, `ptb.discord.com` and `canary.discord.com`. Writes require the `<client id>.discordsays.com` origin. Sessions are issued only after Discord exchanges the authorization code, the member's role is re-read, and the bot token confirms that the instance belongs to this guild and includes the player. Redis stores only a SHA-256 hash of the bearer token. Because the session cookie is `SameSite=Lax`, it is never sent inside the Discord iframe, so framing exposes no signed-in dashboard page.
- **postMessage client.** Messages are accepted only from Discord's origins, the page's own origin, and `null`, matching Discord's Embedded App SDK. Outgoing messages (handshake and `AUTHORIZE`) carry no secrets. The authorization code arrives only by incoming message and is exchanged server-side.
- **Asset route.** Paths are allowlisted by exact patterns, and `..` segments and separators are rejected.
- **Secrets.** `.env` is ignored. No secret uses a `NEXT_PUBLIC_` name. Production refuses to start without `AUTH_SECRET`, `APP_URL`, `REDIS_URL` and the Console credentials, and refuses unauthenticated plain-text Redis on a public host.

## Operator actions

These need access only the operator has. None of them can be done from the repository.

1. **Console URL over HTTPS.** Set `DUNE_API_URL` to `https://…`, or keep it on loopback or a private network. If startup logs the new plain-HTTP warning, fix it before opening the dashboard to members.
2. **Proxy count.** Set `TRUSTED_PROXY_COUNT` to the exact number of reverse proxies in front of the dashboard: 1 behind one proxy such as Cloudflare or Nginx, 2 if both are in the chain, 0 if exposed directly.
3. **Redis.** Use a password, plus TLS (`rediss://`) if Redis is not on the same host or a private network. Do not set `REDIS_ALLOW_INSECURE=true` in production.
4. **Secrets.** Make `AUTH_SECRET` and `BOT_API_TOKEN` distinct random values of at least 32 characters, for example `openssl rand -base64 48`. Make sure `.env` is not readable by other Pterodactyl subusers. Rotate any secret that was ever pasted into chat, an issue or a log.
5. **Discord Developer Portal.** Set the OAuth redirect to exactly `<APP_URL>/api/auth/callback/discord`. Keep `VERIFIED_MEMBER_ROLE_ID` set. For poker, enable Activities on the bot's own application, map the root URL `/` to the dashboard host, and only then set `POKER_ACTIVITY_ENABLED=true`.
6. **Live checks after deployment.** Sign in with Discord and with email and password, sign out, and confirm the old cookie no longer works. Open the poker Activity with two accounts. If poker sign-in returns 429, check which address the logs show for Discord's proxy.
7. **Console API key scope.** Give the dashboard's key only the permissions it reads and writes. Keep the casino and season delivery switches off until they are needed.
8. **GitHub.** Keep secret scanning push protection and branch protection on `main`.
