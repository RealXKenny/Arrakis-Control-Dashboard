# Guild projects, crafting and shared supplies

Roadmap items N051–N060. Two tabs on **My guild** (`/guild?tab=projects` and `/guild?tab=crafting`) let current guild members plan construction, coordinate supplies and run crafting commissions. Everything here is coordination metadata: the dashboard never moves, locks, crafts, buys or sells game items or Solari.

## Access

- Every read and write resolves the signed-in member's linked character and re-reads the guild roster from the Console. Cached names or client-supplied IDs never authorize anything. Outages fail closed.
- Leader-only actions require a freshly verified role-100 character.
- Members are stored and shown only as guild-scoped one-way keys (SHA-256 of the guild and canonical member ID). Canonical Console IDs never reach storage or browsers. Names shown come from the current roster; departed members appear as "Former member".
- API: `GET`/`POST /api/v2/guilds/{guildId}/projects`, no-store responses, same-origin writes, 32 KiB bodies, 60 reads and 30 writes per account per minute, plus the shared verification budget.

## Storage

One Redis hash per guild (`arrakis:{guilds}:projects:{guildId}`) holds a store revision and a strictly validated JSON book of at most 512 KiB. Writes use compare-and-set on the store revision; entity revisions are checked in the pure engine (`features/guilds/projects.ts`), so an unrelated concurrent edit is re-applied against fresh state up to three times while a real conflict on the same record returns a refresh prompt. Uncertain Redis outcomes are never re-sent. Records expire after 90 days without writes, reads do not extend retention, and disbanding a guild deletes the key.

## Not included

- No game writes, transfers, item locks or currency reservations.
- No inventory scanning for the stockpile; quantities are member-declared.
- No completed-sale or purchase history; market estimates are observations of asking prices only.
